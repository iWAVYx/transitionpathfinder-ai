# Atomic Normal Action Updates — Review Only

The normal action-update API previously saved an action, inserted completion activity and marked its linked report out of date in three requests. A later failure could leave a completed action with missing follow-up updates. The eleventh separate draft provides one authenticated-only RPC for the permitted five-field update. Its activity and linked-report metadata effects commit with the action or all roll back.

The RPC requires the actual actor, student, action and loaded microsecond version. Current student reading proof and role locks stay held through commit or rollback. Editors also hold editing proof; an existing assignee can update only while retaining explicit current student reading access. A read-only assignee's completion may mark only the linked report's derived stale metadata, without changing its content or granting report access. Partner-only accounts and Owner/admin accounts without explicit access remain denied.

No-op and legacy/current completion aliases do not duplicate activity. A stale replay or competing update cannot replace a newer committed version. Every action, activity and report-marker receipt is checked inside the transaction; suppressed effect rows roll back the action too. A private timestamp trigger makes subsequent update revisions increase even within one transaction. Neither the RPC nor the timestamp trigger implements a persistent request-receipt ledger.

This is a bounded normal-update component. Existing table policies, grants and raw/trusted writers are preserved. Those other paths can still write outside this RPC, without its atomic effects or loaded-version enforcement, and require their own review. Creation/deletion, goals, caseload/profile/BridgeForward and wider P1 privacy work remain open.

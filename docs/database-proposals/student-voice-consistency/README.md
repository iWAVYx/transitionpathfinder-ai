# Student Voice Saved-Answer Consistency — Review Only

This is the ninth separate review draft after the six document-permission drafts, atomic rights review and progress-access draft. It is not a canonical migration or ledger entry and authorizes no hosted action.

Both Student Voice editors now share one saved-answer workflow. Loads and saves bind the current signed-in account and student; saves compare the exact loaded answer ID/timestamp or expected absence. The database supplies increasing microsecond timestamps, attributes a new answer to the caller and preserves the existing recorded creator on later edits. Empty text intentionally clears the same answer. An uncertain reply stops further writes until an explicit successful refresh. Other drafts, including text entered while a save is pending, are preserved. Student/account departure invalidates replies and success messages.

The database holds canonical student editing proof through writes and current-editor deletion. Read-only student relationships may read; they cannot save/delete. Owner/admin management status alone grants no student access; Partner-only accounts are denied. Raw INSERT/UPDATE and ordinary TRUNCATE are fenced so cached older clients cannot bypass the current save protocol. The original current-editor DELETE capability remains, with current-proof and identity safeguards. Existing rows, legacy prompt keys, recorded creators, grade/demo fields and prior policies remain unchanged.

Every current prompt/reading-level pair is verified against the database API. BridgeForward uses the normalized middle-school reading level. Unknown historical keys remain readable with a plain-language fallback, without being silently rewritten or offered as new editable prompts. Main and BridgeForward prompts come from the same pure catalog. Current student selections are passed into Student Voice links. Unbacked static sample counts and simulated state controls are removed from the signed-in editor; its actual answers remain the source of saved status. Demos remain fictional and do not call private readers/writers.

The workspace panel and report reader share the same account/student-safe load. Failed loads no longer imply empty answers; readers have explicit refresh. Signed-out/demo readers never request private responses. Report notices are screen-only and do not alter document layouts. These are source changes; hosted all-role/mobile/demo acceptance remains under Workstream 7.

The installer pins exact canonical/private access helpers and the role-change guard. It adds three functions (two authenticated-only RPCs and one private trigger helper), four restrictive policies and one trigger. It adds no columns, deletes no data and preserves unrelated routines, indexes, triggers and table permissions. Canonical promotion, current target legacy impact, provider/retention review and an authorized coordinated rollout remain separate.

Verification uses fake-credential disposable databases only: local PostgreSQL behavior, native observed save/removal races across seven role categories, competing creation/update, cached reader/writer checks, current-editor deletion ordering and complete 225 + 41 + nine-draft schema/catalog installation. An authenticated smoke test uses actual installed tables and rolls all fictional rows back. None of these checks connects to staging, production, real accounts, providers or AI.

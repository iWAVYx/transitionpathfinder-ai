# Atomic Rights Review — Separate Review Draft

This follows the six separate document-permission drafts for integration verification. It is not a canonical migration, has no ledger entry and does not authorize hosted execution.

Recording an education-rights planning review now uses one authenticated transaction: append its history, update the student's status/revision and confirm the audit row together. A failure, suppressed row or unexpected receipt rolls the entire transaction back. A dedicated revision prevents a stale form from replacing a newer review. The caller/student identity is explicit, and the existing private editing-proof helper retains the current role and actual student editing proof through commit. The document-sharing, relationships and consent tables are not written.

Private operation receipts store request/actor/student/revision/history/audit identities and a SHA-256 intent hash, not a second copy of notes. Repeating the same request with the same original intent can confirm a lost reply without another history/audit write. It requires current editing access and the actual unchanged history row; a changed intent or missing history is unconfirmed. This confirms the recorded operation, not a claim that it remains the latest student status. No automatic client retry is introduced.

The new read RPC uses one stable snapshot, returns at most20 histories, keeps the actual current operation first and marks legacy status/history mismatches for review without rewriting them. All current eligible writers, including explicitly linked Owner accounts, use the same canonical editing rules. Unrelated, read-only and partner-only accounts cannot save. Partner-only actors cannot read raw history. Raw student rights changes and history insert/update/delete paths are fenced; history is append-only, and ordinary TRUNCATE is revoked. The private operation table is RLS-enabled and inaccessible to ordinary/service roles. Trusted maintenance and parent/cascade-delete review remain separate.

The UI is keyed by account/student, binds the loaded revision, ignores departed replies and fences duplicate actions. An unavailable read is not shown as a successful unknown status. An uncertain save requires a successful explicit refresh before a new request. Read-only viewers have no editing control. The authorization checkbox records the team's planning note; saving it does not create a consent record or change sharing. Legal status labels and guidance are not reinterpreted by this technical change.

Existing status, history, consent, audit and other student values are preserved; only fresh revision UUIDs are added. Existing unmatched or rights-origin consent records need actual-target impact review, not automatic deletion/validation. Notes and legal details are excluded from audit metadata and logs. New notes remain bounded; historical oversized/malformed data and any later changes need the release preflight.

The credential-free disposable job retains all56 inherited installer/catalog stages and all six previous review installers. It verifies all prior public routines unchanged, explicit grants/RLS/triggers, revision-only student backfill and unchanged history/consent/audit/document data. A final real-schema smoke test creates fictional auth/profile/student rows, calls the real authenticated save/read/replay path, checks exactly one history/audit/operation and no consent write, then rolls the whole fictional transaction back. Targeted native tests observe actual cross-role save/removal locks, concurrent writes and cached paths.

This does not close broader non-document privacy, consent/provider/legal approvals, retention/cascade/trusted-writer review, canonical/ledger packaging, final combined regression or hosted acceptance. Fresh authorization is required before migration, deployment or publication.
